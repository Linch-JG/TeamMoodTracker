# Team Mood Tracker

A lightweight internal tool for agile teams to monitor collective well-being through mood tracking and analytics.

## Quick Start

Install dependencies:

```bash
make install
```

Run the backend and frontend together:

```bash
make run
```

The app will be available at:

- FastAPI: `http://127.0.0.1:8000`
- Streamlit: `http://127.0.0.1:8501`
- OpenAPI Docs: `http://127.0.0.1:8000/docs`

## Mood History Management API

Endpoints for managing mood entry history:

- **GET /mood-entries** - List mood entries with optional filtering and sorting
  - Query parameters: `user`, `date_from`, `date_to`, `sort_by` (date/rating), `order` (asc/desc)
  - Example: `/mood-entries?user=Alice&sort_by=rating&order=desc`
- **GET /mood-entries/{id}** - Retrieve a specific mood entry by ID
- **PUT /mood-entries/{id}** - Update an existing mood entry (partial updates supported)
- **DELETE /mood-entries/{id}** - Delete a mood entry

Full API documentation is available at `/docs` when the server is running.

## Analytics & Aggregate Insights API

Endpoints for analytics and aggregate insights:

- **GET /analytics/daily-trends** - Daily average mood trend.
- **GET /analytics/average-mood** - Average mood in optional date range.
  - Query parameters: `date_from`, `date_to` (inclusive, `YYYY-MM-DD`)
  - Example: `/analytics/average-mood?date_from=2026-04-01&date_to=2026-04-14`
- **GET /analytics/mood-distribution** - Mood distribution buckets.
  - For a single day: `target_date=YYYY-MM-DD`
  - For a period: `date_from`, `date_to`
  - Example: `/analytics/mood-distribution?target_date=2026-04-10`

In Streamlit, the **Analytics** tab includes:
- daily trend chart,
- average mood metric for selected period,
- period distribution barplot,
- single-day distribution barplot.


Run tests:

```bash
make test
```

Run tests with coverage:

```bash
make coverage
```

Generate HTML coverage report:

```bash
make coverage-html
```

```bash
make security
make audit
make load-test

make docs-check
```

Remove local caches:

```bash
make clean
```


The coverage gate ensures:
- All new code is properly tested
- Existing functionality remains covered
- Quality standards are maintained across the project

## OpenAPI/Swagger Completeness Gate

OpenAPI is generated by FastAPI and validated in CI:
- required paths are checked,
- each operation must have `summary` and `description`,
- responses must provide at least one example (except pure no-content responses).
